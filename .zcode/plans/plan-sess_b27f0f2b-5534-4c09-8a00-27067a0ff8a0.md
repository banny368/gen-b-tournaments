# Gen B Tournaments — Full Platform Build Plan

## Goal
Build the complete esports tournament platform from `Gen_B_Tournaments_Master_Build_Prompt.md` as a real, tested, production-ready system — mobile-first Next.js PWA + free-tier backend — then deploy it live.

## Locked Decisions
- **Stack:** Next.js 15 (App Router, TypeScript) + Tailwind CSS + shadcn/ui, PWA-enabled (installable on Android), i18n (English/Hindi/Gujarati via next-intl)
- **Backend:** Supabase free tier — PostgreSQL, Auth (email/password + Google), Storage, Realtime (chat/lobby)
- **Deploy:** GitHub → Vercel (free) + Supabase cloud (free). User will set up the 3 free accounts.
- **Scope:** Full platform, built phase-by-phase with verification gates (never declare complete until the master audit passes)
- **Money rule (per master prompt):** Server-authoritative double-entry ledger, idempotent flows, real-money features OFF behind feature flags/compliance gates until legally approved. Demo mode with demo credits for testing.

## Architecture
- **UI:** Premium dark esports theme (deep navy/black, electric blue accent, glass surfaces, subtle glow), lucide-react SVG icons only (zero emojis), skeleton loaders, reduced-motion support. Bottom nav on mobile, sidebar + data tables on desktop.
- **Server-authoritative logic:** All money/tournament/permission decisions live in PostgreSQL functions (RPC) running in transactions with row locks — join flow, ledger credits/debits, deposits approval, withdrawals, prizes. Next.js Route Handlers only for webhooks/admin privileged calls with service-role key (server-only). Client displays server state only.
- **Key flows:**
  - *Join:* `join_tournament()` RPC — one transaction: status check → registration window → capacity (row lock, race-safe) → eligibility → wallet debit via ledger → entry insert. Idempotency key prevents double-join/double-pay.
  - *Manual UPI deposit:* unique reference code → user submits UTR (unique constraint) → admin reviews → approval credits ledger. Duplicate/reused UTR impossible at DB level.
  - *Payment gateway:* PaymentProvider abstraction (Razorpay / Cashfree / ManualUPI adapters). Razorpay sandbox adapter + HMAC-verified webhook route; disabled by flag until keys exist.
  - *Withdrawals:* configurable slab fee engine, KYC state machine, admin review queue, locked balance + reversal via ledger. OFF in production until compliance.
- **Admin panel** (first-class, /admin): granular RBAC (8 roles × ~16 permissions), MFA-ready, audit log (append-only) on every sensitive action, commission/fee/reward settings, feature flags, deposit & withdrawal queues, user management (no direct balance edits — adjustments via reason-required ledger transactions), tournament manager, claims/disputes, moderation, analytics dashboard, legal content versioning.

## Database (~45 tables, SQL migrations kept in repo)
users/profiles, roles/permissions/user_roles, games/game_modes, tournaments/tournament_rounds/tournament_entries, teams/team_members, clans/clan_members, chat_channels/chat_members/chat_messages/chat_reports, wallets/ledger_transactions/ledger_entries/deposits/withdrawals/payment_orders/payment_events/refunds/commissions/prizes, reward_campaigns/reward_grants/ad_reward_events/referrals, notifications/claims/claim_messages/attachments/kyc_records, risk_events/audit_logs/legal_documents/legal_acceptances/admin_settings/feature_flags/announcements. RLS on every table; indexes per query pattern; UTC timestamps throughout.

## Build Phases (each: implement → run → test → verify → document)
1. **Setup & Research:** scaffold repo, save this plan as `PLAN.md` (progress tracker), Supabase project + migration runner, env templates, verify toolchain, CI (GitHub Actions: lint/test/build).
2. **Foundation:** design system + component library, PWA shell (manifest, icons, offline page), auth + profiles, RBAC schema, games/categories (admin CRUD), i18n scaffolding, seed data (BGMI/Free Fire/COD + demo tournaments).
3. **Tournament Engine:** full data model + 13 statuses (server-driven transitions), listing/search/filters, details with server-time countdown, race-safe join flow, room credential release (hidden until eligible), results entry.
4. **Wallet & Ledger:** double-entry ledger, 7 balance types, transaction history, demo deposits, manual UPI + UTR flow, idempotency everywhere.
5. **Payments:** provider abstraction + Razorpay sandbox adapter + verified webhook + payment event log. Real keys → live later.
6. **Withdrawals:** request flow, slab engine, KYC state, admin queue, reversal. Flagged OFF for production.
7. **Social:** clans + clan chat (server-enforced membership), global chat (realtime, rate limits, moderation, profanity filter), leaderboards (server-side views), notifications (in-app + email).
8. **Rewards:** referrals (qualification-gated), daily/campaign rewards, reward ledger, anti-abuse caps/velocity checks. Ad-reward stub disabled pending policy check.
9. **Admin Panel (full):** dashboard analytics, all managers & queues, settings, audit log viewer, announcements, claims/disputes, simulation sandbox mode.
10. **Security & Performance:** RLS + authorization audit, rate limiting, upload security (type/signature/size, private storage + signed URLs), security headers, dependency scan, admin MFA, the 15 critical money tests (double-join, duplicate webhook/UTR, retry storms, cancellation/refund/payout idempotency), pagination/caching/image optimization, low-end + slow-network testing.
11. **Release:** final master audit (functional/financial/tournament/social/security/UX/performance), legal pages (versioned + acceptance records), user & admin guides, production build, **deploy live**: GitHub push → Supabase migrations → Vercel env vars → production smoke tests. Compliance-dependent features clearly marked disabled.

## Testing

## Final Deliverables
Live URL + repo, architecture/API/env docs, admin & user guides, QA report, known limitations + compliance checklist.
